# 产品说明：从跨场疑点到下一稿复核

ScriptGraph 面向编剧和剧本统筹。核心任务是把阅读中发现的疑点连同原文保存下来，带着修改要求逐场改稿，生成下一稿后核对具体变化。工作台接受自己的剧本，也提供可编辑的原创教学示例。

默认入口是 [本机剧本改稿工作台](https://daizhouchen.github.io/scriptgraph-rag/)。Python GraphRAG 与固定合成集评测位于 [技术实验室 `#lab`](https://daizhouchen.github.io/scriptgraph-rag/#lab)，不承担用户导入剧本的自动分析。

## 完成一轮可验收的改稿

首次体验可从「用完整示例走一遍」开始。《末班放映》包含 8 场初稿、已确认的人物／道具，以及 2 项预设人工审阅任务。示例修订稿补足钥匙与票根的交接，并增加一场配电间动作。下列流程也适用于自己的文本。

| 步骤 | 使用者操作 | 可以核验的结果 |
|---|---|---|
| 1. 确认剧本结构 | 导入 UTF-8 Fountain / TXT 或粘贴文本，点击「解析并预览」；检查场次、行号和候选名称，再确认创建 | 原文按确认后的边界完整分场；误识别名称可以取消，补充道具后才参与索引 |
| 2. 查回原文 | 在「查证原文」搜索示例中的「黄铜钥匙」，分别使用原文检索与关系扩展 | 结果区分直接命中和关系补充；每项可打开所属版本的原文，关联结果展示实体与场次路径 |
| 3. 精确留下依据 | 打开来源，点击行号选一句，Shift + 点击扩展或填写起止行；带着选中原文建任务，写明修改方案与验收条件 | 引用严格保留指定版本、场次、起止行与原文；同一句出现多次也不会跳到第一处 |
| 4. 带着任务改场次 | 在任务点击「去修改相关场次」；检查基准稿与当前场，修改正文，按需新增、删除或上下调整场次 | 草稿独立于正式版本；原稿可读、相关任务可查，旧引用不变。等待保存成功后刷新，可回到最近编辑场继续 |
| 5. 生成一份修订稿 | 点击「生成修订稿」，检查诊断、顺序与新行号；修正空场、缺正文或多场头等问题，再确认 | 仅通过校验才新增正式版本并清除这份草稿；失败时原稿与草稿均保留，无改动不生成重复稿 |
| 6. 按变化安排复核 | 在「版本与复查」看增删行，再打开优先复核任务；对照旧引用与新版候选，采用或重新选择精确行段，填写结论 | 原文变化、上下文变化、调序、未变和歧义有分别说明；只有提交人工复核才记录为已核对当前版本 |
| 7. 导出并继续工作 | 导出指定两版的改稿记录；另存 JSON 备份，再恢复为新项目 | 报告说明当前任务状态与尚未复核组；备份带回正式稿、未完成草稿、实体、任务和有效引用，不覆盖原项目 |

可以先记没有引用的待办，但没有原文依据的任务不能标为「已解决」。当前稿本复核至少需要一处该版本的有效原文；若某场已删除，可引用新版相邻场并说明处理结果。

每步都应等顶部保存成功再依赖刷新后的结果。「已保存到此浏览器」包含未完成草稿的保存，不等于已经生成正式稿，也不等于任务已解决。

## 导入先确认，不把格式识别当理解

支持 UTF-8 的 `.fountain`、`.txt` 和粘贴文本。识别「内景／外景／内外景」、带场序的中文场头、`INT.` / `EXT.` 等 Fountain 场头与点号强制场头。标准 Fountain 标题页保留在原文中，不计入场次；首场前的非标题页内容会作为待确认片段保留。

没有识别出场头时，完整文本保留为一个「未分场内容」，可以填写起始行重新预览。手动分场须从第 1 行开始，严格递增、不能重复或超出原文范围。已提交的稿本不就地重切；需要修正时通过新版导入重新确认，避免旧引用漂移。

人物来自 `@姓名`、对白格式、大写姓名及独行短中文等规则候选；独行短中文可能是动作或对白，不默认确认。道具候选来自显式 `【道具：名称】` 标记，也可手工补充。导入前应取消误识别项，之后可维护标准名称、别名和是否启用索引。文字格式不会被当作创作事实。

文件读取上限为 6 MB，文本上限为 200 万字符；超限会提示分集或缩短文本。以上是输入保护，不是处理速度承诺。

## 草稿是可续写的工作区

「开始逐场改稿」从当前正式稿建立一份草稿，保留基准版本与各场来源。可以修改正文、新增场次、删除场次、上下调序，也可对照或还原当前场原文。修改一场不会把相邻场或标题页一起重写；草稿中的新增场次没有伪造的历史来源。

草稿正文、名称、顺序和最近编辑场随项目保存。保存完成后离开编辑区或刷新，可以继续写；不承诺恢复光标位置。右侧的相关任务与原稿关联材料供核对，人物／道具共同出现不表示那一场必然需要修改。

生成前会预览场次及行号，并检查非空场次、可识别的单一场头、正文、长度、版本数量和基准版本。没有正文变化或实际调序时不生成重复版本。已确认边界的原稿场次若原样保留，会沿用原场头与边界；非标准场头或未分场片段会提示复查，不要求用户为修改其他场次重做全部分场。修改或新增场次仍需符合场头规则。

「放弃本轮草稿」和删除／还原场次都需要明确确认。取消确认不改正文；确认放弃只移除未生成的草稿，正式版本与任务保留。生成失败也不会先删除草稿。草稿可单独导出 Fountain 文本，但继续完整工作应使用 JSON 备份。

外部已经改好的稿件仍可通过「导入外部新版」加入。有未完成草稿时会先返回编辑区，须先生成或明确放弃后再导入，避免覆盖草稿基准。逐场生成的版本有明确来源链；外部导入没有这条编辑来源，只能据实际原文保守匹配。

## 查证提供材料，不替创作者作结论

「只查原文」按字词匹配。多个词用空格分隔时，必须在同一场全部出现；`第 5 场` 按当前稿本序号定位。中文使用明确子串，拉丁名称按字词边界匹配，不进行同义词推断或语义问答。

「原文 + 关系扩展」先保留直接命中，再沿「命中场次 → 已确认人物／道具 → 其他提及场次」补充材料。没有直接命中时，不凭图关系生成结果；未确认实体不参与扩展。每个补充结果显示实际路径和引用，用户需要打开原文判断它是否相关。

## 任务状态和稿本复核是两件事

每项任务包含标题、判断／修改方案／验收条件、一处或多处依据，以及「待处理」「修改中」「已解决」「保留设定」状态。筛选和搜索帮助安排工作；「导出全部任务」包含全部任务、来源及当前稿本复核状态，不只导出屏幕筛选结果。

引用固定绑定所属版本与场次，而不是当前列表中的第几个场。打开旧任务时，源文窗口明确标出「历史稿本」，并保留当时的行号和摘录。任务可以继续补入新版依据；旧引用不会自动替换为新版内容。

生成或导入下一稿后，任务的处理状态保留；是否已核对当前版本单独记录。系统比较最近有效复核所用的引用组，没有该组时使用最新有有效引用的版本。更早的历史依据继续可读，但不会反复触发已处理过的旧变化。

| 依据分级 | 可以据此判断什么 | 仍需人工完成什么 |
|---|---|---|
| 引用未变 | 引用与唯一对应的整场原文未变；无关场次修改或编号顺移不提高优先级 | 打开对应原句，确认是否沿用，不能自动算作新一稿已复核 |
| 同场上下文有变化 | 引文本身逐字保留，同一场其他文字有改动 | 判断上下文是否改变原结论 |
| 引用位置有变化 | 场次相对顺序改变，或两稿中的唯一原句出现在另一位置 | 核对顺序、场次身份与创作含义 |
| 引用原文有变化 | 唯一对应场次不再完整保留原引文 | 阅读真实新版整场候选，重新选择所需行段 |
| 未找到原引用／对应待确认 | 可能删除、改名、重写或存在重复，不能可靠确定对应 | 手动寻找新版依据；不按旧场号、第一处同句或相似意思猜测 |
| 缺少有效依据 | 还不能追踪这项待办的原文变化 | 先附上有效原文 |

唯一对应整场完全未改时，重复对白仍可按原相对行段准确定位；整场发生变化而重复句无法唯一对应时，则保留歧义。变化分级不是语义影响预测，更不会自动改变任务处理状态。

复核窗口并列显示旧依据与新版候选，可展开差异、采用候选，或在同一窗口重新选择场次和行段。候选不会自动加入。阅读并附上新版依据后点击「确认本轮复核」；关闭或取消不会提交结论。若移除了该次复核所需的全部该版依据，相应复核记录会被清除。

## 版本差异保持保守

新版以独立版本保存，原稿可以单独导出。逐场生成的版本先沿明确场次来源对应；其他场次按规范化内容寻找唯一对应，再尝试唯一场头。结果列出内容修改、新增、删除、调序与「对应待确认」，并显示实际增删行及两侧行号。

插入一场导致后续编号顺移，不直接算作调序。只有已匹配场次之间的相对先后关系改变才标记顺序变化。没有明确来源且重复场头无法唯一对应时留给人工核对，不按场号猜测；新增／删除也可能由改名或无法配对引起。

文字对照默认聚焦增删行及邻近上下文，可展开完整场次。长文本超出精细匹配预算时会提示降级，两稿全部原行仍然保留，但增删数量不代表最小编辑量。行差异不等于逐字修订标记，也不识别剧情含义。

「版本与复查」可以选择两个稿本比较；选择比较目标不会把历史稿设为当前工作稿。导入的新稿成为当前稿本，任务复核围绕当前稿本进行。

## 报告用于交接，不冒充事件历史

版本页的「导出本轮改稿记录」按所选的比较前／比较后版本生成 Markdown，包含场次标题、行增删、原引用和新版候选，以及任务当前处理状态、已有目标稿复核记录、尚未复核组和没有依据的待办。未生成的编辑草稿不参与正式版本比较；报告里的任务分级以所选目标版为准，界面任务复核仍围绕当前正式稿。

系统没有逐次操作事件日志。因此报告不会把一项现在为「已解决」的任务说成本轮刚解决，也不能证明何时、由谁完成修改。任务备注和最后更新时间是当前保存记录，不是完整审计历史。

## 保存、导出与恢复的边界

项目保存在当前站点的 IndexedDB，不提交给应用后端，也没有账户或云同步。文件由浏览器读取；页面仍需加载站点静态资源。不要把「本机保存」理解为自动备份或跨设备可用。

修改后页面显示保存中、已保存或失败状态。正式稿、草稿、任务都走同一套保存。失败时保留当前页面里的修改，并提供重试和备份。若读取旧记录失败，不会用空项目覆盖它；先尝试重新读取。清理浏览器站点数据会失去本地记录。

同时打开多个标签页不会自动合并修改。如果另一页面先保存，本页会停止写入并提示冲突；先备份本页修改，再重新载入最新记录。恢复备份可将本页工作保留为独立副本。

导出用途不同：

- 正式稿／草稿 `.fountain`：保存所选文本，草稿文件明确标为未完成。
- 全部任务 `.md`：当前审阅任务及原文依据。
- 改稿记录 `.md`：所选两版差异与任务当前状态。
- 项目 `.json`：用于完整恢复，包含正式版本、未完成草稿、场次来源链、索引、任务及引用。

当前采用 schema 3，可读取原 schema 2 项目库和备份。原有库在校验后继续使用同一项目，保留历史 ID、文本和引用，后续成功保存为新格式；旧版不认识的新数据不会静默当作空库。已经打开的上一版客户端写入旧快照时，会由库修订号冲突保护阻止覆盖新记录。它不是自动合并，遇到冲突应先备份再重新载入。

手动恢复 JSON 时校验格式、标识、原文覆盖、行号、摘录、场次来源链和草稿完整性。未通过时不导入；通过后可修改副本名称再创建新项目，原项目保持原样。接近容量上限时，可缩短副本名称后重试。可恢复尚未满足生成条件的草稿，继续修正；不得借校验之名丢弃未完成正文。Markdown 和单份 Fountain 不包含全部项目状态，不能代替 JSON 备份。

## 技术实验室与尚未提供的能力

`#lab` 保留两部公开固定语料的检索样例、连续性候选和改稿关联查看；本地 FastAPI 还能运行原检索引擎。四部合成剧本上的固定评测仍为 provisional，不能视为对任意导入文本的能力证明。

新工作台不提供实时 LLM、语义问答、自动冲突检测、自动改写、剧情影响预测、多人协同或商业剧本云托管。当前可验收的是：用户能把自己的原文带入流程，沿可解释关联查证，保留任务和历史依据，并用新版原文明确完成一轮复核。尚未报告真实用户效率或创作质量提升。
