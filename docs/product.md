# 产品说明

ScriptGraph 服务于编剧、制片和剧本统筹。它把长剧本中的人物、场景、道具、事件与版本组织为可追溯知识图谱，让用户完成三个任务：查证原文事实、发现连续性风险、判断改稿影响。

首版不生成剧情，也不替创作者决定“矛盾是否合理”。所有抽取信息保留原文位置和复核状态；证据不足时拒答。

## MVP

- Fountain/TXT 分场解析
- BM25、字符向量、混合检索和图扩展四种方法
- 证据问答、一致性审校、改稿影响分析
- 中文原创合成数据、固定评测集和人工复核队列
- 本地完整模式与公开受限 Demo

## 暂缓

商业剧本托管、视频理解、分镜生成、多人协作和文生视频不在首版范围内。

## 公开工作台的使用流程

### 查证原文

选择剧本，再选择本剧的样例问题，或输入人物、道具、场次与线索编号。样例结果来自同源 Python 引擎的预计算快照；自由输入使用浏览器关键词查找，只列候选原文，不声称形成语义答案。四种检索方案仅对预计算问题生效。未知编号、跨剧本对象与找不到依据的输入有明确反馈。

点击「打开原文」查看完整场次及准确行号，可以前后翻场，也可以到仓库核对源文件。保留合成语料的事实标记，避免把这些规则输出误当作对真实剧本的理解能力。

### 连续性复核

候选从同一份解析结果产生，按称谓、知情状态、道具归属和时间顺序分类。每项展示两侧设定和原文入口，用户可以标记待复核、需要调整、创作设定或待讨论，并填写备注。筛选用于安排工作，导出包含全部候选、真实来源和当前复核状态。

本次复核标记在切换任务和剧本时保留，刷新页面即清除；不会写入远端、修改原剧本，也不会替代数据集作者的正式复核。

### 改稿核对

从当前剧本的真实人物与道具中选择对象，填写改稿计划。工作台按对象在原文中的直接关联列出场次，用户打开原文逐场核对，再导出计划和核对进度。修改对象或计划后，旧结果清空，需重新生成。

这是一份人工核对清单：计划文字随清单导出，工具不预测改写后的剧情，不自动传播设定，也不改写文件。

## 首次体验与边界

首页直接进入工作区，提供本剧三个代表问题。工程方法与阶段性指标收在可展开说明中。公开页不接实时 AI、Neo4j 或向量服务，不上传剧本。所有公开材料为原创合成数据，实验结果仍为 provisional。
